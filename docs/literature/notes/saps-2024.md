## Mechanism
The patient simulator (SAPS) is a pipeline of LLM prompts, run per turn. (1) State tracker: classify the doctor's turn into one of five types using a single-token (logit-biased) prompt: inquiry, advice, demand (physical action), other topics, conclusion. For inquiry and advice, two more prompts decide specific vs. ambiguous, and whether the patient record contains the answer (output the matching text). This yields 10 states: initialisation, effective / ineffective / ambiguous inquiry, effective / ineffective / ambiguous advice, demand, other topics, conclusion. (2) Memory bank: long-term (the record, retrieved only for effective states), working (a fixed response rule per state, e.g. ambiguous question: ask the doctor to be more specific; ineffective question: deny or say unsure; demand: refuse as it is an online consult; other topics: redirect), short-term (dialogue history). (3) Response generator: one prompt with record excerpt, state rule and history. So 3 to 5 LLM calls per turn. The paper uses this simulator to test doctor LLMs (AIE).

## Evidence
Simulator test set: 50 real hospital cases, GPT-4 and human reviewers produced 4,000 doctor questions with labelled action types, 10 rounds each. Six metrics (Accurate, Passive, Cautious, Honest, Guidance, Focus): SAPS is closer to human-played patients and more stable across turns than plain GPT-4 and other simulators, and improves on every metric versus GPT-4; its state-tracking accuracy is slightly below humans (figures only, no exact values in the text). Doctor-LLM evaluation: 7 LLMs on 50 HospitalCases + 150 MedicalExam cases, diagnosis accuracy GPT-4 64.0%, ChatGPT 60.0%, QianWen 56.0%, ChatGLM3 48.0%, XingHuo 34.0%; GPT-4 judge scores correlate with human judgments across 28 metrics, automated metrics less so (DISTINCT highest). Also found: models could extract more information by repeated vague questions, hence the "ambiguous" state.

## Limitations
- Action space and rules defined by observation; authors say it must be broadened.
- Metrics separate strong from weak models but not similar ones.
- Simulator accuracy shown in figures; exact numbers and the simulator's base model are not stated in the text.
- Multi-call pipeline and online-consult assumptions (no exam, "demand" is refused), not a face-to-face OSCE.

## For Rapport
**Verdict:** idea-only. No licence, but the idea is directly useful: classify the doctor's turn first (specific / vague / unanswerable / off-topic / physical request), then apply a fixed rule per state. In the Digital Twin this belongs as a cheap pre-classifier in code (keywords plus the exam-command router) that sets the allowed disclosure and a hint for the single structured call, and as test labels in the self-play evaluation. The vague-question trap (an over-generous patient lets doctors fish) matches our trust locks.
